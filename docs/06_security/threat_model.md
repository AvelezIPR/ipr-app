## 1. Metodología

### 1.1 Alcance
- **Sistemas:** app Flutter (por crear), BFF `/mobile/v1` (por crear, en el Next.js existente), Next.js web existente (solo donde comparte proceso o la amenaza se hereda), WordPress/WooCommerce (`ipr/v1` existente, `ipr/v1/m/*` propuesto, *handoff*, checkout), Cloudflare, Wompi (solo la interfaz con WooCommerce), CI/CD.
- **Fuera de alcance:** la infraestructura interna de Wompi, de Cloudflare y del hosting Plesk; ingeniería social a empleados; seguridad física.

### 1.2 STRIDE
S = suplantación · T = manipulación · R = repudio · I = divulgación de información · D = denegación de servicio · E = elevación de privilegios.

### 1.3 Criterio de probabilidad (P)

| P | Nivel | Criterio explícito |
|---|---|---|
| 1 | Rara | Requiere acceso privilegiado (servidor, BD, cuenta administrativa) o una cadena de fallos improbable; sin incentivo económico evidente. |
| 2 | Improbable | Requiere condiciones específicas: dispositivo robado o con malware, secreto filtrado, error de configuración no demostrado, o habilidades avanzadas. |
| 3 | Posible | Superficie expuesta en Internet y explotable con herramientas comunes por un atacante motivado; o error de configuración con indicio en el código. |
| 4 | Probable | Ataque automatizado habitual contra comercio electrónico (*credential stuffing*, *scraping*, spam, bots) sobre una superficie pública sin control efectivo hoy. |
| 5 | Casi cierta | Ocurre de forma continua en cualquier sitio público del sector o ya es observable. |

### 1.4 Criterio de impacto (I)

| I | Nivel | Criterio explícito |
|---|---|---|
| 1 | Insignificante | Sin datos personales ni efecto económico; molestia menor. |
| 2 | Menor | Datos públicos o comerciales no sensibles; degradación breve; costo operativo bajo. |
| 3 | Moderado | PII de un usuario o de pocos; interrupción parcial de una función; pérdida económica acotada; incumplimiento menor. |
| 4 | Mayor | Toma de cuentas, PII de muchos usuarios, fraude o pérdida económica significativa, interrupción de la compra o de la web; posible queja ante la SIC. |
| 5 | Crítico | Compromiso de secretos de servidor o de cuentas administrativas, fuga masiva, fraude de pagos, sanción regulatoria probable o daño reputacional grave. |

### 1.5 Nivel de riesgo
**Riesgo = P × I.** Bajo: 1–5 · Medio: 6–11 · Alto: 12–19 · Crítico: 20–25.
- **Riesgo actual:** con los controles que **existen hoy** (para amenazas heredadas) o sin los controles propuestos (para amenazas nuevas).
- **Riesgo residual:** estimado **si** los controles propuestos se implementan y sus pruebas se aprueban. No está verificado.
- Desempate dentro del mismo valor: (a) impacto económico o PII masiva, (b) existe hoy en producción.

### 1.6 Actores (atacantes)

| ID | Actor | Capacidad |
|---|---|---|
| AT-1 | Atacante remoto anónimo / bots | Peticiones HTTP masivas, listas de credenciales filtradas, *scrapers*, proxies rotativos. |
| AT-2 | Cliente autenticado malicioso | Cuenta propia válida; modifica peticiones (proxy), app reempaquetada. |
| AT-3 | Atacante con acceso al dispositivo de la víctima | Dispositivo robado/compartido, malware, root/jailbreak, copias de seguridad. |
| AT-4 | Atacante en la red | Wi-Fi hostil, proxy con CA instalada por el usuario o MDM. |
| AT-5 | App maliciosa en el mismo dispositivo | Registra esquemas/rutas, lee portapapeles, capturas. |
| AT-6 | Atacante de cadena de suministro | Paquete npm/pub/plugin comprometido, acción de CI comprometida. |
| AT-7 | Interno o tercero con acceso privilegiado | Administrador de WordPress, hosting, CI, Cloudflare. |
| AT-8 | Defraudador de campañas / competidor | Automatiza abuso de flujos de negocio (precios, ruleta, PQRS). |
